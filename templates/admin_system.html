System

Master-admin only. Use these if the app or the Pi itself gets stuck and you're not physically there to power-cycle it - they work as long as this page is reachable at all (over wifi or Tailscale), even if SSH isn't.

A cron job checks this every 5 minutes and posts a Pi Health Alert on the dashboard if it goes above 75°C or the Pi reports throttling.

Restart the App

Restarts just the OpsHub program itself (a few seconds of downtime). Try this first if something in the app seems stuck or misbehaving - it's much faster and lighter than a full reboot below.

Reboot the Pi

Restarts the whole Raspberry Pi - use this if the app restart above doesn't help, or if something like SSH or the network itself seems hung. Everyone using OpsHub will be disconnected for roughly 30-60 seconds while it comes back up.

Shut Down the Pi

Safely turns the Raspberry Pi off so you can unplug it, move it or work on it without risking the SD card or the database. OpsHub will be offline for everyone until it's turned back on, and the uptime monitor will send its "OpsHub is down" alert while it's off - that's expected.

  1. Tap Shut Down Pi below.
  2. Wait until the Pi's green light stops blinking (about 20-30 seconds). The red light may stay on - that's fine.
  3. Now it's safe to unplug the power.

Turning it back on:

Once the Pi is off, this page can't reach it, so there's no "on" button here - it has to be done at the Pi. Unplug the power cable and plug it back in (on a Raspberry Pi 5 you can instead press its small power button once). OpsHub comes back up by itself in about a minute; just reload this page.

Heads up

The restart and reboot buttons need this page to load at all - if the Pi is fully offline (powered off, no network, completely hung), nothing remote can reach it and someone will still need to be there in person. These help with the "the app or SSH got stuck but the Pi itself is still up and reachable" case, which is the much more common one.
